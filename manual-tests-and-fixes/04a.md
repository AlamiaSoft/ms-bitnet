No, **Linux portable isn't necessary for your immediate goal**.

I mentioned it only because the same runtime could later target cheap VPSes, but that's premature.

For your use case I'd simplify to:

```text
                BitNet
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
   Docker image       Windows portable
   (current)          (low-end laptops)
        │                   │
     server/VPS          no Docker
```

### And yes — Windows portable likely means a build somewhere

But **not on your machine**.

The ideal pipeline is:

```text
Microsoft BitNet source
        ↓
GitHub Actions
        ↓
Windows x64 build
        ↓
GitHub Release
        ↓
bitnet-windows-x64.zip
```

Containing something like:

```text
bitnet/
├── bitnet-server.exe
├── models/
│   └── ggml-model-i2_s.gguf
└── start.bat
```

Then the low-end laptop user does:

```text
Download ZIP
    ↓
Extract
    ↓
start.bat
    ↓
localhost:8080/v1
```

**No Docker. No CMake. No compiler. No Ollama.**

And importantly, the **model doesn't necessarily need to be bundled** in the GitHub Release. I'd keep:

```text
bitnet-windows-x64.zip       ← runtime
BitNet-b1.58-2B-4T.gguf      ← model download
```

so the executable is reusable across multiple BitNet models.

So yes: **CI builds it once → GH Release stores it → laptops consume it.**

But I'd finish cleaning the current repo first. Then we can add a small `windows-portable` packaging project rather than complicating the working Docker setup.
