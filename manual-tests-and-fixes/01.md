# Task: Diagnose and Fix BitNet Chat Generation Quality

## Context

We already have a working Dockerized Microsoft BitNet inference service on Windows.

Current verified state:

* Windows + Docker Desktop / WSL2
* Linux BitNet container
* Microsoft BitNet commit: `0b341e5`
* llama.cpp submodule: `390c307`
* Model: `microsoft/BitNet-b1.58-2B-4T`
* Model file: `ggml-model-i2_s.gguf`
* Model parameters: ~2.4B
* Model disk size: ~1.18 GB
* CPU-only inference
* 4 CPU threads
* ~25–28 tokens/sec
* ~242 MB observed Docker working-set memory
* server starts in ~5.2 seconds
* HTTP server available at:

```text
http://localhost:8080
```

* `/v1/models` works
* `/v1/chat/completions` works
* Ollama exists separately on:

```text
http://localhost:11434
```

Ollama must remain completely untouched.

---

# Problem

The browser UI exposed by the BitNet server is reachable at:

```text
http://localhost:8080/?new_chat=true#/
```

When sending:

```text
hi
```

the model produces severely degenerate output similar to:

```text
Hi, it's a human. In this example, the assistant is a bit.
The assistant is a bit of a human.
The assistant is a bit of a human.
The assistant is a bit of a human.
...
```

The output repeats the same phrase many times.

This indicates that the basic inference pipeline works, but the chat/instruction serving configuration may not be correct.

DO NOT assume the model itself is defective.

Diagnose the actual cause.

---

# Primary Objective

Make the BitNet server produce sane conversational responses for the official `BitNet-b1.58-2B-4T` model through:

```text
POST /v1/chat/completions
```

and through the built-in browser UI, if the UI uses that endpoint.

The desired result for:

```text
hi
```

should be a short, coherent response rather than repetitive text.

# Phase 4 — Verify Chat Template

Do NOT manually prepend a chat template if the server already applies it.

The objective is:

```text

        ↓
server
        ↓
GGUF chat template
        ↓

```

If the server is not applying the template correctly, fix the server invocation/configuration rather than changing the model.

Do not permanently modify the GGUF unless absolutely necessary.
